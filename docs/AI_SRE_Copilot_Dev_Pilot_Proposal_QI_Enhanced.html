Executive Summary — One-page decision brief

The ask, the why, and the conditions

Situation: SRE toil is dominated by alert triage, log correlation, and runbook lookup — slow, inconsistent, and audit-heavy. Complication: Naïve AI automation risks prompt injection, privilege creep, and unapproved changes. Question: Can we prove, in a safe QI sandbox, that an AI-assisted copilot accelerates diagnosis without weakening change control?

Answer (pilot thesis): Yes — if we enforce a hard separation: AI proposes → deterministic policy validates → human approves → protected workflow executes → health checks verify → audit records persist. The copilot never holds deployment credentials; the deployer never sees raw prompts.

Strategic Context

Situation & Imperative — Why this pilot, why now

◈ Market & technology tailwinds

Observability (Cloud Monitoring + Grafana) and LLMs (Vertex AI Gemini) have converged to make evidence-linked diagnosis feasible. Workload Identity Federation removes the need for long-lived keys. Together they allow a recommendation-first copilot that is both useful and controllable — a materially better trade-off than 12 months ago.

⬢ QI-specific opportunity

QI runs lean, multi-region Cloud Run estates. SRE load is bursty. A copilot that correlates alerts, pulls bounded evidence, and surfaces runbook-backed next steps — inside QI’s own project — builds reusable IP before any client conversation. This pilot is an internal capability bet, not a client delivery commitment.

Zero-trust, least-privilege, audit-first

Usefulness without trust expansion. The AI is the least privileged actor in the system. Privilege is concentrated in a single, audited, approval-gated workflow — and is unavailable everywhere else.

Mandatory Security Controls — Checklist (preflight)

⬡ Identity & Access

  • Workload Identity Federation with short-lived credentials; no long-lived SA keys
  • Federation trust restricted to QI GitHub org / repo / protected branch / environment / workflow
  • Narrow roles + SA impersonation only where required; avoid project-level broad grants
  • Privileged creds only in protected execution job, post-approval

◈ Data & AI Safety

  • Redact secrets / sensitive payloads before model call; synthetic / QI-approved data only
  • Treat logs, incident descriptions & runbooks as untrusted input
  • No prompt content can alter policy or invoke tools directly
  • Token budgets, timeouts, schema validation, safe failure on malformed output

◎ Platform Hardening

  • Grafana + intake: authn/authz, restricted network, rate limits
  • Audit logging enabled (cost-assessed); retention limits enforced
  • Artifact & secret storage access scoped to executor identity only
  • Branch protection + environment protection on GitHub

₵ Cost & Abuse Controls

  • Request limits, concurrency caps, token budgets
  • Budget alerts at 50/75/90/100% — alerts are notify, not hard caps; operational stop procedure tested
  • Daily spend review during fault-testing windows
  • Idempotency + deduplication to prevent runaway remediation
⚠

Responsible AI guardrails

Every recommendation must include: evidence citations, confidence, risk, validation result, and rollback plan. Low-confidence or uncited proposals are auto-rejected by policy. Human reviewers are shown the exact bounded evidence the model saw — no hidden context.

Go / No-Go Rule — Non-negotiable

Privileged remediation remains disabled until every applicable bypass test demonstrates enforcement. The pilot coordinator + security reviewer must jointly sign the gate. No exceptions, no “temporarily allow”.

◈ Rollback discipline

Post-action health checks run automatically. Failed or inconclusive recovery is escalated; rollback follows a separately authorized path — never an auto-rollback triggered by model output. Rollback proposals are themselves subject to approval binding.

◎ GitHub protections (to be confirmed at readiness gate)

Protected environment with required reviewers, branch restrictions, and environment-scoped secrets. Verify QI repo plan supports required protections; if not, document limitation and alternate compensating control before Week-1.
